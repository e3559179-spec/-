# 章节复盘与全书总结

用户请求章节复盘、阶段性总结或全书总结时读取。默认输出 Markdown，使用实际原文和已保存记录完成可阅读的文稿；不要只交付提纲、空表或工具生成的草稿。工具负责固定依据和保存，助手负责文本分析与内容核对。

## 1. 确认任务和记录依据

用户说“读完一章/全书了”是已读声明，不是掌握证据。先按 [记录格式](record-schema.md) 保存本轮实际变化；仅说“生成全书总结”不能擅自填入全书已读状态。用户希望阅读中途做全书视角整理时，可标为阶段性总结。

用 [持久保存工具](persistence-workflow.md) 读取当前完整版本。不要用最近会话摘要替代问题、实际回答、解释、纠错历史和覆盖范围；也不要挑选旧快照中更漂亮的通过结果充当当前状态。

章节复盘优先使用当前已明确的章节。目标含糊且会影响取材时，问一个必要定位问题。全书总结不强制用户重新提交所有记录，已有资料足以做限定总结时先完成可有据撰写的部分，并注明缺口。

准备记录包：

```sh
python skills/classic-reading-companion/scripts/review_document.py prepare --book-dir "reading-data/my-book-v1" --kind chapter --chapter "原文中明确的章节名"
python skills/classic-reading-companion/scripts/review_document.py prepare --book-dir "reading-data/my-book-v1" --kind book
```

按需要运行其中一种。`prepare` 返回 `status: draft`，在该书 `reports/draft-<id>/` 保存完整 `evidence.json` 和待撰写 `draft.md`。它不读取书籍正文、不生成论证分析、不证明全书已读，也不改变进度。首次使用无需额外依赖，只需 Python 3 及同目录保存/校验脚本。

记录包固定 `basis_save_id` 和原记录内容。章节筛选只使用记录中的确切章节标记，不做关键词猜测；未定位记录、跨章覆盖区间或缺少终点章节的范围会单列为待核对。助手应检查这些材料，不能直接丢弃，也不能自动算入该章。包内保留整本记录供核对，章复盘正文只使用相关内容。

## 2. 核对覆盖，不用缺席记录推定理解

先检查版本和原文来源。书目来自用户自述但尚未核验时如实标注；不能因记录有文件路径就声称目前原文可访问。

根据实际材料形成简短覆盖说明；全书总结通常可用表格，章节复盘用一段话即可。分别说明：

- 用户声明读到的范围；
- 实际伴读、讲解到的范围；
- 经过检查的具体知识点及检查局限；
- 有原文可分析但没有伴读记录的部分；
- 原文或记录均缺失、边界无法确认的部分。

有核验目录时可依目录列章节；目录未知时只列已确认部分，并说明不能穷举未覆盖章节。不能从最远页码、最大段落号、问题数量或一次“读完了”计算全书完成率，更不能用若干检查通过推导“整章已掌握”。

依据当前原文补充未伴读部分是允许的，但必须标为“本次基于原文的补充梳理”，而不是用户过去的学习成果。若原文也缺失，写明无法有据整理的范围，不用模型对名著的一般印象填补。

## 3. 完成章节复盘

参考 [章节模板](../assets/chapter-review.template.md)，通常写成一份短复盘，按难度与记录量调整，不强制固定字数：

1. 本章处理什么问题，论证或叙述如何推进，在已获得的上下文中起什么作用；
2. 一至几个真正重要的概念或论证关系，指出关键原文位置；
3. 重要疑问及有实际表达支持的理解变化；
4. 少量待重读、待检验或仍有争议的事项，以及用户主动提出的思考。

简单章节不机械填满所有栏目；不要将复盘再变成完整逐段重讲。没有用户问题或理解表达时可写“暂无这方面记录”，不能为显得完整编造一段成长过程。

## 4. 完成全书总结

参考 [全书模板](../assets/book-review.template.md)，在范围说明后覆盖以下内容；证据不足的项说明不足而不是补造：

| 内容 | 所需依据和写法 |
| --- | --- |
| 全书核心问题与论证结构 | 用实际文本说明作者试图回答的问题、主要判断和支撑联系；区分文本明示与助手重建，保留论证缺口。 |
| 各章节作用及相互关系 | 按核验顺序解释承接、转折、例证或推进；涉及未伴读章节时注明来源，不假称已经检查过。 |
| 关键概念及具体用法 | 给所在段落、限定条件和不同语境的用法；不把异质概念排列成看似顺畅的固定链条。 |
| 重要问题与理解变化 | 依据实际提问、回答和修正历史，有前后表达才能写变化；有提示的通过须保留帮助条件和目标范围。 |
| 未解决问题与重读清单 | 分开列待解决、待检验、仍有争议及用户指定回顾点，给位置、理由和具体行动；未检查不称为已证实薄弱。 |
| 用户思考、质疑和延伸问题 | 仅使用用户实际表达，注明原话或概括。不同意作者不自动归入理解偏差。 |
| 研究素材及出处 | 仅收录实际核验、有用途的材料，给作品/版本/章节或页码/链接；没有则写暂无。不得自动扩展成文献搜集项目。 |

避免只有各章摘要的拼接：在依据充分的范围内说明章节之间如何连接。助手仍不能把自身解释的完整性当作用户理解的完整性。

## 5. 区分三种声音并处理历史

正文采用自然的小标题、段落标注或表格，读者应能明确分辨：

- **作者的观点**：准确转述或短引文，给原文定位；不得将助手补出的前提归给作者。
- **助手的解释**：概念释义、结构分析、推测与比较说明其依据和局限；备选读法不是未经核验的学界共识。
- **用户的思考**：依据问题原话、`understanding_at_time`、`understanding_changes`、检查回答或历史中的实际表达；没有原话就不补写。

作者观点至少定位到本次可访问的原文，或记录中已保存且足以支持论断的明确原文证据；后者注明本次是否重查。仅保存了助手一句解释、没有可回溯的原文依据时，最多作为待核对的旧解释，不升级为作者定论。

用户的重要问题保留原始意思，可短引原话，标明问题记录 ID 和原文位置。助手主动发起的检查放入检查回顾，不能列为“用户问过的问题”。概括用户思考时注明是概括，避免代用户说“我终于认识到……”之类未表达的结论。

记录旧误读和纠正有助于理解变化时，可以展示它们，但注明哪个是旧解释、哪个已更正。撤回或待复核的检查不支撑当前已掌握结论；不因为某个历史检查曾通过就跳过新出现的偏差。恢复旧快照后的报告仅反映选定版本，不能把恢复后未保留在当前版本的经历写成已经包含。

## 6. 引用和内容验收

重要论断旁给简短原文定位。问题变化旁给记录 ID/检查 ID，并在文末说明其对应同目录 `evidence.json` 中的哪条记录。当前目录已核验时可采用章节与段落引用，不需要把所有存储字段写入正文。

本次额外查验的原文或研究素材，另列准确来源和核验范围；它不自动进入过去的伴读记录。不同译本分开标识。不用总目录链接替代具体论断的依据，不伪造页码、引文或完整参考文献。

封存前逐项审阅：

- 范围说明与实际记录相符，空白章节、跳读、未检验点未被写成掌握；
- 三种声音清楚，用户观点和变化能回到实际表达；
- 已撤回评价不再被采信，争议没有被消解为定论；
- 关键论断有原文依据，助手推论及本次补充已标明；
- 重读建议针对具体点，有位置和理由；
- 文稿已实际写成，没有残留模板提示、空白栏目、草稿标记或虚构的示例；
- 没有因缺少资料而用无依据的泛泛书评冒充完整的全书总结。

这项内容审阅由助手完成，不把它说成用户已经审定。用户可以之后提出修订；不要求先通过一次额外考试才能获得总结。

## 7. 封存与交付

把完成的 Markdown 保存成独立候选文件，例如该草稿目录内 `authored.md`，然后运行：

```sh
python skills/classic-reading-companion/scripts/review_document.py finalize --book-dir "reading-data/my-book-v1" --packet "prepare返回的evidence.json路径" --content "已撰写并审阅的authored.md路径"
```

工具验证依据记录未被篡改、当前保存版本没有变化、镜像没有冲突，以及文稿非空且已移除草稿标记；它**不验证正文含义、引文真实性或总结质量**。删除草稿标记本身不代表内容验收通过。

成功后在 `reports/<new-report-id>/` 保存 `review.md`、完整 `evidence.json` 和最后写入的 `manifest.json`；清单记录报告类型、范围、依据保存 ID 和文件哈希。每次封存使用新目录，不覆盖旧报告，不改变阅读进度、检查结果或问题状态。只有清单完整且回读校验成功时才报告已保存。

版本已更新时，重新准备记录包并核对差异后修订文稿；不得只替换包内 ID 以绕过校验。写入失败时保留候选和部分输出，说明未完成保存，不将缺少清单的目录当作最终报告。

交付可点击的最终文档路径，简要说明覆盖范围及主要缺口。记录包包含本书完整学习记录；只分享正文时不自动公开旁边的记录包。没有运行工具的条件时，仍应在对话中给出有依据的完整文稿，并说明文件尚未封存，不能只停在“可以生成”。
