# 随读答疑与读后讲解

每次文本解释遵循 [文本理解方法](reading-method.md)。这里决定何时回答、回答多少，以及怎样衔接记录。

## 先识别当前请求

用户问某句话、某个概念或某个推论时，进入随读答疑；用户说“这一段读完了”“这几段读完了”并要求讲解时，按其范围进入读后讲解；用户给出了自己的理解时，先回应其实际表达。

用户直接要求“讲解这段”时也按明确请求解释该范围，不强制要求先说固定口令；但没有读完声明就不能把它记为用户已读。用户说“读完了”且范围清楚时，不必再次要求确认。

不要仅凭“继续”就推断要讲下一段：已有明确的待续讲解范围时接着讲；否则先恢复已有位置，只有歧义会影响行动时再问一个必要问题。用户提出具体问题时优先处理该问题，暂存尚未讲完的范围。

## 随读答疑

1. **定位。** 利用已给出的文本、位置或短定位片段锁定问题；已明确的不重复追问。用户只说“这是什么意思”且没有可指向材料时，请其提供所指文字。
2. **先答当前疑点。** 通常先给一小段直接解释，再补决定性的语句、指代或论证联系。用户只问一个词时，不从整部理论体系讲起。
3. **按需展开。** 句法困难就拆长句，概念困难就分析本处用法，推论困难就展开理由与结论。必要时分别说清字面意思与理论含义；只有存在相关争议时才讨论争议。
4. **处理不确定性。** 关键指代或省略不能确认时，说明有限的可能解释并询问所缺片段，不猜上下文。对可独立确定的部分仍可回答。
5. **记录并收束。** 保存问题原话、位置、已有用户理解、解释与依据。一般答疑不自动附加测验，不把每次提问变成逐段授课。用户继续讨论就沿当前问题推进。

答疑时可以读取解释所必需且可访问的上下文；读取上下文不授权提前讲完整章，也不改变用户已读范围。用户明确要求跨段或整章比较时，才按扩展后的范围处理。

## 难点诊断与分层讲解

从用户正在问的文字和实际表达选择讲法，不要求用户先学会给困难分类。能判断就直接帮助；不同卡点会明显改变解释时，只问一个容易回答的定位问题。用户说“我也说不清”时，可以先取原文最小的有意义单元，给一个短解释作为尝试，再根据反馈调整；不把这种尝试写成已确认的用户缺陷。

| 当前表达提示的障碍 | 优先采用的讲法 |
| --- | --- |
| 某个词不知道在这里指什么 | 指出它在本句中的对象、限定或对比；必要时区分日常含义与本处用法。 |
| 词认识，但长句读不顺 | 先抽主干，再接回否定、修饰、转折和指代；给能与原句对应的改写。 |
| 两句话分别懂，不明白如何连接 | 保留已懂的两端，集中解释关系；分别指出文本明示、助手重建与仍缺的依据，不用整章背景替代连接。 |
| 解释仍太抽象 | 选一个贴切例子、反例或两种读法的对照，说明它对应原文的哪层关系以及不能说明什么。 |
| 缺少理解当前句子所需的概念或背景 | 先补最小且有依据的前置知识，说明它怎样帮助理解本句，再回到当前文字；不展开一套背景课程。 |

这些是讲解选择，不是新增的问题类型或对用户能力的判断。未确认的卡点可暂存为解释尝试的理由，不能据此登记“背景不足”或“理解偏差”。

讲解通常先给直接、易懂的一层；用户需要时再展开句子、概念或论证。每层解决一个当前障碍，最后对应回决定性的原文用语。简单问题一层就够，不把所有层次一次倾倒给用户，也不机械填“字面—理论—背景”等栏目。先判断用户是否已经提供了理解表达，有则直接利用，不要求重复复述。

## 仍不懂时调整解释

“还是不懂”“能不能再直白一点”“这两个词我懂，但为什么……”表示上一种解释尚未解决当前需求，不等于用户整体能力不足。先检查自己的解释是否有跳步、循环定义、未说明的术语或误读，再决定怎样调整。

- **保留已懂部分。** 用户已说明理解某概念，就从剩下的连接讲起。必要澄清只问一个定位问题，不同时发理解检查；这是为了选讲法，不是考试。
- **改变解释路径。** 拆出更小的关系、将难句改写、对照容易混淆的两种说法，或用例子与反例帮助辨认条件。不是把上一段加长或替换同义词；也不是必须每轮都举例。
- **把帮助带回原文。** 例子使用户点头后，仍应说明原文中哪个词、条件或连接与之对应。类比不能证明作者观点正确；必要背景和隐含前提继续遵守来源及不确定性规则。
- **按实际反馈决定下一步。** 用户已表达准确的关系时，直接说明准确范围；用户仍有具体障碍时继续处理。只有“好的”“懂了”时尊重其自述，不反复要求证明，也不登记通过。需要检查时遵循下节的一题规则及暂停偏好。
- **解释遇到边界时说明。** 原文缺失、译文有歧义或论证本身缺乏支撑，就指出具体限制。不同讲法仍未解决时，可提出重读一句、补一段上下文或先暂存该点；不无限循环、不擅自推进，也不强迫用户暂停。

同知识点的重讲追加到既有记录。用 `explanations` 保存实际解释与原文依据，用 `history` 保存用户反馈和本次为何换讲法；有具体剩余障碍时写入 `follow_up_actions`，续读时据此接着处理。只记录实际表达和尝试，不替用户补写学习变化，不新设“教学成功”状态。用户明确仍不懂后，单凭再次讲解不将“待解决”改成“已解释待检验”；后续状态依实际表达和现有状态规则调整。

## 读后逐段讲解

保持原文段落次序与边界。PDF 换行不等于新段，跨页也不等于分段；分段不明且影响讲解时说明采用的工作分段依据。若为了易读把长段拆成几个讲解小节，注明它们仍属于同一原文段。

每段先指出位置或简短定位片段，再围绕主要意思讲解。下面是可选分析角度，不是每段必须填满的表格：

| 需要解决的问题 | 如何展开 |
| --- | --- |
| 这段在说什么 | 用一两句话概括本段主张或作用，保留必要条件。 |
| 哪句话难懂 | 只拆相关难句，解释句法、指代、转折及有依据的省略。 |
| 概念在此处是什么意思 | 用当前段落的定义、对照或用例解释，不贴通用词条。 |
| 理由怎样支持结论 | 指出文本明示的联系与助手重建的前提，不抹平论证缺口。 |
| 为什么这里讲这一段 | 依据实际上下文说明承接、转折、例证或推进作用；上下文缺失时不编造。 |
| 哪种读法容易出错 | 指出可能遗漏的条件或超出原文之处；这只是阅读提醒，不能当成用户已犯的错误。 |

多段都已读完且用户要求一起讲解时，按顺序逐段完成，可以在末尾简要说明段落之间的联系，不用每段问一次“继续吗”。范围过长无法在一次回复中充分处理时，明确本次讲到哪段、剩余哪段，写入待续讲解事项；不要用一段摘要冒充已逐段讲完。

解释重复概念时，简要承接先前已经核对的用法；本段用法变化时再展开。不把助手先前解释直接当作新的原文证据。

## 理解检查与节奏

这里规定与讲解衔接的基本规则；实际出题、反馈、分类和状态更新时，继续读取 [理解检查与追踪](understanding-workflow.md)。

- 用户要求检查，或刚讲的关键关系值得核对时，可用一个简短问题让用户复述、解释关系或辨别说法。一次只检查一个关键点，不在一个问句里塞多个任务。
- 发出检查题时不附标准答案、示范复述或等同答案的暗示；允许已有讲解包含理解所需知识。问后停下并等待，不替用户作答，也不紧接着推进下一段。
- 多段讲解默认完成本次约定范围后再考虑一个检查；用户要求逐段停顿或中途主动问问题时依其节奏处理。
- 用户跳过、说“先讲别考试”或只想讨论时，尊重其选择，不马上换一道题。记录跳过不代表通过或失败。
- 已有用户表达足以反馈时直接评价，不为了走流程重复出题。评价参照原文及限定条件，而非与助手答案的词语相似度；有依据的异议不等于未理解。

## 记录与进度的对应

按 [记录格式](record-schema.md) 维护现有字段，第一阶段的 JSON 结构继续适用：

| 实际发生的事 | 应怎样记录 |
| --- | --- |
| 用户问一句话 | 新建具体问题或追加同知识点追问；未知的当时理解留空。一般不改变已读位置。 |
| 助手解释一个句子 | 将解释、依据和疑点写入问题记录；不把该段或整章标为已完整讲解。 |
| 用户声明读完某几段 | 更新用户声明范围；助手尚未讲解的段落仍未讲解。 |
| 助手完成一段讲解 | 只更新实际完成的讲解位置及覆盖范围，不推断用户掌握；没有真实疑问时不为凑记录创建理解障碍。 |
| 助手提出检查，用户未回答 | 记录待回答检查。尚无问题条目时，可创建由本次检查产生的知识点记录，`question_verbatim` 和 `understanding_at_time` 留空，`checks.question` 保存助手问题；`history` 注明“助手发起检查”，不冒充用户提问。 |
| 用户深入讨论或不同意作者 | 保存实际观点，可归为延伸探究或解释争议；理解状态是否适用另行判断。 |
| 用户指出助手误读 | 追加助手纠错历史，保留用户原话，不把助手错误记为用户理解偏差。 |

纯讲解没有问题条目时，至少在 `coverage`、讲解位置和会话摘要保存本次处理范围及简短说明。不要把每个预设的“易错点”写成用户的实际薄弱点。

记录仍按本轮及时保存的规则执行。对用户的回复以阅读内容为主，保存成功可简短提示；读写失败必须说明，不让教学回答掩盖保存失败。
