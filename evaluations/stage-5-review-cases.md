# 第五阶段总结情境检查

情境为虚构测试要求，不是用户真实学习经历。对照 [总结流程](../skills/classic-reading-companion/references/review-workflow.md) 审阅。

本阶段已进行下列静态规则审阅，并运行 [报告工具的 14 项程序测试](../tests/test_review_document.py)；连同已有功能共 54 项程序测试通过。程序测试验证取材标记、版本和文件行为，不能证明模型能准确总结某部原著。未执行独立模型的真实原文语义评估。

| 情境 | 应观察到的文稿与行为 |
| --- | --- |
| 用户声明全书已读，记录仅覆盖第一章 | 可以生成全书视角的限定总结；明确其他章没有伴读记录，不写全书已掌握。只有实际原文可访问时，才能补充其他章分析，并标明本次补充。 |
| 没有核验目录，也没有其他章节材料 | 只列已确认范围，说明无法穷举缺失章节；不猜章节名、顺序或完成比例。 |
| 章节复盘中有无法定位的问题和跨章区间 | 保留为待核对材料，人工核对后再决定是否使用；不自动丢弃或算入该章。 |
| 用户没有提问，只有助手发起的理解检查 | 区分检查与用户问题，不在“用户问过的问题”中伪造提问。 |
| 用户只表达过一次理解 | 可以呈现这一次表达，不能编造“从误解到掌握”的变化。 |
| 某检查历史上通过，但后被助手撤回 | 作为旧评价及更正过程呈现，不再用它支持当前掌握结论，也不将助手错误归因于用户。 |
| 用户准确理解作者，但提出反对意见 | 在用户思考中保留其质疑，区分理解与赞同，不列为理解偏差。 |
| 记录有助手解释但缺少可回溯原文 | 标为待核对旧解释；不能直接改写成作者确定主张。原文可取得时应重新查验。 |
| 完全没有研究素材 | 文稿说明暂无，不自动搜集文献、编造出处或强行联系专题。 |
| 工具刚生成空白模板和记录包 | 状态为草稿；助手必须实际撰写并进行内容核对，不将其交付为最终总结。 |
| 写作期间出现新的阅读记录 | 封存拒绝旧依据，重新准备并核对文稿差异；不能只替换记录包中的保存 ID。 |
| 文稿写出，但完成清单失败 | 保留候选和部分输出，报告未完成保存；不改变阅读状态，也不覆盖旧报告。 |

后续真实试读时保存实际输入、输出和文稿，再按这些标准审阅。不要将这份预期行为表描述成已经发生的模型运行结果。
