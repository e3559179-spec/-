# 第三阶段情境检查

这些情境用于审阅 [理解检查与追踪](../skills/classic-reading-companion/references/understanding-workflow.md) 及 [记录约定](../skills/classic-reading-companion/references/record-schema.md)。材料和用户表达均为虚构，不是经典引文或用户真实学习经历。

本阶段已进行下表的静态规则审阅，并运行 [19 项程序测试](../tests/test_tracking_validation.py)。程序测试覆盖记录约束、退出码、旧格式提醒和不修改输入文件；不能证明模型出题或反馈质量。未执行独立模型行为测试、跨会话保存恢复测试。

| 情境输入 | 应观察到的交互与记录 |
| --- | --- |
| 用户刚听过解释，只说“好的”，没有回答检查题 | 不写已掌握，不补造理解原话；待回答检查不能成为通过证据。 |
| 原文“只有取得材料，才可能判断”；用户回答“有材料就一定能判断” | 指出必要条件被扩大为充分条件，保留其正确识别条件关系的部分；给出原文依据后记需修正。 |
| 同一题用户回答“没有材料就谈不上判断，但材料齐全也未必够” | 可认定本题关系表达准确，不因措辞与助手不同判错；保存目标、回答、反馈、依据与当前通过关联。 |
| 用户首次主动提供了正确理解，要求评价，此前没有表达 | 可作表达评估，助手题目字段为空；称首次可观察表达，不虚构从错误到正确的变化。 |
| 用户看了完整示范答案后原样复述 | 记录示范答案后的表现，不能仅凭复述自动推定独立理解；若目标关系仍无法判断，则无法判定。 |
| 用户在定向提示后，用自己的话准确解释了关键关系 | 可以对这个有提示条件下的表现判通过，记录支持条件，不泛化为无提示或整章掌握。 |
| 用户暂停主动检查，后来只临时要求检查一个点 | 执行这次请求，不擅自解除暂停偏好，不在其后每段追问。 |
| 某点早先有有效通过记录，用户跳过新的复习题 | 这次结果已跳过，原有通过保留；不能改成未掌握。 |
| 通过后用户对同一点表达了与原文相冲突的新判断 | 重新打开本点，清空当前通过关联但保留历史检查和新表达依据；不修改其他点或评价整体能力。 |
| 助手发现先前评分错误，旧检查原本没有足够证据 | 撤回或待复核旧检查，不让它继续支撑当前通过；保留错误历史而不是删除记录。必要时用新评价关联旧检查。 |
| 用户准确复述作者观点，同时质疑其理由不足 | 理解准确与评价争论分开，可分别记录；不以不同意作者判理解失败。 |
| 用户问一个新的独立概念，之前的条件关系已经通过 | 建新知识点记录，旧通过不受影响；同位置不等于同知识点。 |
| 用户要求复习清单，记录中有待检验点和明确仍不懂的点 | 分别标注待检验与待解决，给位置和理由；不把未检查点称为已证实薄弱点，也不自动创建提醒。 |

## 程序测试对应的证据范围

- 无回答、无反馈或空依据不能支撑有效的通过或需修正评价。
- 被撤回或待复核的检查不能支撑当前通过；错误历史可以保留为提醒，不要求删除。
- 当前通过关联不能跨知识点、引用待回答结果或包含重复/无效 ID。
- 主动表达评估可以没有助手题目；不适用检查的讨论可以使用空理解状态。
- 旧格式缺失扩展字段时提示核对，不凭空补写；显式无效字段不会当作旧字段缺失。
- CLI 使用中文和空格路径，验证读取错误、无效 JSON、约束错误和成功返回码；运行前后输入字节不变。

实际运行模型情境时应保留输入、输出与记录变更，逐项对照观察标准；不要将这份预期行为表当成已经发生的运行结果。
